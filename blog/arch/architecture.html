Corporate Case Law on Databricks: the build that ran

A rule earns its way into the law (top), then an agent can decide only through that law (bottom). Every box below ran end to end.
ADMIT A RULE
1Decision history Delta tables · Unity Catalog
120K decisions, one commit per month. Each month is read as of that month: 11.6% of facts were edited later.
2Mine + compile Python miner · rulec.py
Mines where decisions disagree with policy. LLM-proposed rules must pass the trusted compiler.
3Moot court Lakebase branch · SQL warehouse
One branch per trial (ready in 5 s). Replay must gain accuracy and break no rule. 3 LLM-proposed rules rejected.
4Outcome screen SQL warehouse · Delta outcomes
Uses only outcomes known at the time. The rogue approver's rule is flagged as bad law, even when re-proposed.
5Activate CREATE FUNCTION · law_events
The rule becomes a SQL function named by its SHA-256 hash. The event is appended to the log.
THE LAW UC functions h_<sha256> + Lakebase law_events
9 active rules, verified exactly (tamper tests detected). Python and SQL agree on all 5,029 replay cases. The log is append-only: UPDATE, DELETE, TRUNCATE blocked.
USE THE LAW
6New case deal + free-text note
32 new deals; 8 notes carried a prompt-injection attempt.
7Clerk agent Foundation Model API · Claude Sonnet 5.5
Decides only by citing rules. 32/32 followed the law; 0 of 8 injections followed.
8Checker re-runs the cited UC functions
Reproduces each decision from the law: 0 overrides needed. Same result under a second principal.
