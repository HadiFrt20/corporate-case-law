# Architecture Decision Records: Corporate Case Law (CCL)

Format: Context · Decision · Consequences · Status. Dates are 2026.
Background: CCL was born on 16 Oct from studying the CLM paper (arXiv 2609.04377; notes in `docs/CLM_PAPER_NOTES.md`).

---

## ADR-001 · Learning artefacts are one continuous hand-drawn whiteboard
**Context.** The paper study needed a visual walkthrough. A slide-style storyboard was rejected earlier ("waaay too slidey").
**Decision.** One continuous Excalidraw canvas: roughness 1, Excalifont, sticky notes, numbered zones, arrows that carry the story, no frames. Board 1 = CLM paper, Board 2 = CCL to its right on the same canvas. Generated by script (`whiteboard/clm_board.py`, `whiteboard/ccl_board.py`) with the shared `exd.py` helper.
**Consequences.** Boards are reproducible and diffable. Rendering checked with the skill renderer plus browser screenshots. The renderer truncates very tall canvases, so check in row crops.
**Status.** Accepted.

## ADR-002 · Excalidraw runs in an isolated browser context
**Context.** The default excalidraw.com storage in the automation Chrome holds another board. Loading a file replaces the canvas.
**Decision.** Always use the Chrome DevTools isolated context `clm-paper`. Files are served by a localhost CORS server (port 8765) and loaded via a synthetic drop event.
**Consequences.** The other board is never touched. Isolated storage is ephemeral, so the source of truth is the `.excalidraw` file on disk.
**Status.** Accepted.

## ADR-003 · Walkthroughs run themselves
**Context.** The user asked for no manual "next" steps ("do it in an automatic way").
**Decision.** Inject a self-advancing tour: a narration panel plus a timed camera glide using synthetic `WheelEvent` (scrollX -= deltaX / zoom). Zoom is set once via the localStorage `excalidraw-state` key plus a reload. Back / pause / skip buttons are optional.
**Consequences.** The tour is lost on page reload and must be re-injected. Screenshots time out unless the tab is brought to the front.
**Status.** Accepted.

## ADR-004 · Core thesis: tacit knowledge = the residual of written policy
**Context.** CLM (the paper) never specifies a tacit-capture mechanism. Its skills are typed in by hand, which is the 1980s knowledge-acquisition bottleneck.
**Decision.** Corporate context is mined from decision exhaust. Compute what the written policy ("statute") would decide, then mine only the cases where logged decisions disagree with it. Vocabulary borrowed from common law: statute, precedent, holding, appeal, dead letter.
**Consequences.** Works only where decisions are logged as structured events (pricing approvals, credit, claims, refunds, escalations). The "because" is not recoverable from structured data alone.
**Status.** Accepted (thesis), validated on synthetic data only.

## ADR-005 · A holding is an executable predicate
**Context.** CLM's "explainable by construction" explains which skill was picked, not what the model output.
**Decision.** Holdings take the firm's own shape, `WHEN <conjunction of literals> THEN max discount = X` (or a stricter reject). On Databricks this becomes a governed UC SQL function, with support / replay precision / outcome lift / steward recorded in COMMENT and ABAC scope. Agent answers must cite holding IDs, and a checker re-runs them under the requesting user's identity (OBO).
**Consequences.** Explanations can be executed and audited. The same predicate shape limits what can be expressed (see ADR-016).
**Status.** Accepted.

## ADR-006 · Admission by point-in-time replay ("moot court"), regression-safe
**Context.** Mined rules can fit noise. Context should earn its way in.
**Decision.** A candidate holding is admitted only if replaying the most recent held-out months (facts as of each decision date; Delta time travel in production) raises accuracy AND every already-admitted holding keeps precision >= 0.8 on the cases it actually decides. The v1 check of "accuracy up" alone was insufficient and was fixed in v2.
**Consequences.** This is the defensible novelty ("CI/CD for corporate context"). It costs one replay per candidate (a Lakebase branch per candidate in production).
**Status.** Accepted.

## ADR-007 · Bad-law filter uses outcomes, but only once they are knowable
**Context.** Copying past decisions also copies bad habits (the rogue approver). v1 read renewals for deals made last month, which is future leakage.
**Decision.** A loosening holding whose approvals renew >= 0.20 worse than policy-approved deals is "bad law" and goes to steward review instead of to the agent. A renewal is only observable at `month + 12 * term`. With too few known outcomes the holding is "pending" (admitted, marked).
**Consequences.** Requires a long enough history (the simulation moved from 24 to 48 months). Detection is threshold-bound: a -0.30 effect is caught, a -0.15 effect is missed.
**Status.** Accepted.

## ADR-008 · Falsify on a synthetic firm first, with a pre-set kill rule
**Context.** "Novel" ideas need cheap falsification before any real pilot.
**Decision.** Synthetic firm with planted tacit rules (ground truth known). Kill rule written on Board 2 before v2: KILL if CCL < policy + 10 pts OR fewer than 4 of the hidden rules are recovered exactly. Note: the earliest wording said "4 of 6", and the planted set became 7 (6 loosening + 1 stricter).
**Consequences.** Rule recovery can be measured. Synthetic data cannot prove real-world validity.
**Status.** Accepted. v1 failed the bar (3/7); v2 passes (+15.0 pts, 6.7/7).

## ADR-009 · Score against two targets
**Context.** Agreement with logged decisions rewards copying the rogue approver. The ECC review showed that the v1 headline (0.931) silently included the rogue rule.
**Decision.** Report every method on `vs_actual` (logged decisions, including rogue approvals and noise) and `vs_good` (policy-consistent, noiseless decision of a well-run firm). Report CCL both with and without the bad-law filter.
**Consequences.** Headlines can't hide which target is used. `vs_good` is defined by the simulator, which is an assumption.
**Status.** Accepted (v2).

## ADR-010 · Baselines
**Decision.** (a) Statute only, equivalent to perfect RAG over the policy document. (b) Gradient boosting retrained monthly on the trailing 12 months. (c) Gradient boosting plus outcomes: approved-but-known-not-renewed relabelled as "should reject", trained on 24 months because no outcome inside 12 months is known yet (a first version silently saw no outcomes; fixed). Also a static GBM, logged but not headlined.
**Consequences.** (c) is a naive outcome-aware baseline. A proper uplift / counterfactual model is still missing.
**Status.** Accepted, with a known gap.

## ADR-011 · Schema-guided miner, stricter law first
**Context.** Generic decision trees fragment rules (v1: 0.7/7 recovered). In v2, R4 and R5 looked impure because Germany SMB cases, which the stricter rule rejects anyway, polluted their precision.
**Decision.** Exhaustive subgroup search over conjunctions of up to 3 literals (segment, region, term, booleans, round deal-size thresholds 100/250/500/1000k) times a cap grid, greedy cover with a length penalty. Tightening holdings are mined first, and loosening precision ignores the cases they decide. Tree and covering miners are kept as comparators.
**Consequences.** Recovery rose to 6.7/7. The search space matches the generator's rule shape (see ADR-016).
**Status.** Accepted.

## ADR-012 · Rule-recovery metric: "the rule applies" semantics (changed after results)
**Context.** v2's first pass scored word-for-word correct holdings (e.g. `renewal AND churn_high AND disc <= 22`) as 0. Purity was measured against the rule that *binds* each case, so a correct rule was "impure" wherever a higher-cap rule also applied.
**Decision.** A holding states rule r correctly if >= 80% of the cases it decides (excluding cases overridden by the stricter Germany rule) are cases where r applies, and it covers >= 60% of them. Scored on a fresh 60K sample, not on training months.
**Consequences.** Disclosed on Board 2 and in RESULTS.md as a post-hoc metric change. The tree miner still scores 0.7/7, so the metric is not trivially lenient.
**Status.** Accepted, flagged as post hoc.

## ADR-013 · Numbers are generated, never typed
**Context.** v1 board numbers were hand-copied and partly single-seed (ECC review item 5).
**Decision.** `ccl_sim.py` writes `runs/*.json` (miner, seed, outcome effect recorded); `aggregate.py` writes `summary.json` and `RESULTS.md`; `whiteboard/ccl_board.py` reads `summary.json`.
**Consequences.** Re-running regenerates everything consistently.
**Status.** Accepted.

## ADR-014 · Keep history; delete only proven duplicates
**Decision.** v1 code and results are archived in `v1/`. `runs_prefix/` holds the first v2 grid (before the stricter-law-first fix and the 24-month baseline fix). `v1/run_seed7.json` was deleted: an unlabelled duplicate of `run_tree_7.json`.
**Status.** Accepted.

## ADR-015 · ECC plugin at project scope
**Context.** The user asked to install `affaan-m/ECC` "for this project".
**Decision.** `ecc@ecc` 2.2.3 at project scope (`.claude/settings.json`), hooks enabled with the `standard` profile, rule packs `common` + `python` copied into `.claude/rules/ecc/`. Its `python-review` drove the v2 fixes (`ecc_python_review.md`).
**Consequences.** About 33K tokens are added to every session opened in this project. Its rules ask for TDD / 80% coverage, which is not applied to this research script (deliberate).
**Status.** Accepted.

## ADR-016 · Positioning and scope
**Context.** Prior art: decision traces as the missing context layer (Foundation Capital "Context graphs" essay), decision-trace schemas (Solozobov, arXiv 2604.09296 / 2605.04093 / 2606.20634), the CBR 4R loop (Aamodt & Plaza 1994), concept drift (Gama et al. 2014). A prior-art agent's patent suggestion and its "70% novel" figure were not adopted.
**Decision.** The novelty claim is narrowed to: replay as the admission test for agent context, plus mining the residual against written policy, plus outcome-weighted precedent. Biggest open threat: the planted rules share the miner's shape, so the next experiment uses hidden rules outside it (OR rules, interactions, odd thresholds), then LLM-written rationale, then real decision data.
**Status.** Accepted.

## ADR-017 · v3 hard world: hidden rules outside the miner's shape
**Context.** v2's biggest caveat: planted rules had exactly the shape the miner searches for.
**Decision.** A second world with an OR rule, a term-scaled cap, an odd threshold (340k), a field v2 never used (tenure >= 11y), and a negation. The rogue rule and the Germany rule are kept. The easy world is kept bit-identical (verified).
**Consequences.** Tests generalisation of the mining approach, not just of one schema. The hidden rules are still a designer's choice.
**Status.** Accepted.

## ADR-018 · Beam miner over generic literals
**Context.** The schema miner's literal list was hand-picked (it can't see tenure, negations, 340).
**Decision.** Literals are built from every column: category = / !=, boolean / NOT, numeric > and <= at deciles plus round sizes. Beam search (width 25, depth 3), the same greedy cover and gain as schema, stricter law first.
**Consequences.** It recovers the hard world far better than schema (6.7 vs 3.7 of 7) and matches schema exactly on the easy world. It is slow (about 13 min per run) and needs vectorising before real volumes.
**Status.** Accepted.

## ADR-019 · Fairest baseline: black box + renewal veto
**Context.** v2's "beats the black box" compared CCL (with outcome filtering) against black boxes without equivalent outcome logic.
**Decision.** GBM decisions are vetoed on exceptions when a renewal model (trained on approved deals with known outcomes, 24-month window) predicts renewal >= 0.20 below policy-approved deals. Same information, same threshold, no rules.
**Consequences.** It matches CCL on the well-run target. The accuracy advantage claim is retired; CCL's claim becomes "equal accuracy, readable and governed form".
**Status.** Accepted.

## ADR-020 · Stricter law overrides any approval
**Context.** Error analysis on the hard world: a tightening holding only overrode cases inside the policy, so loosening holdings approved German SMB deals above 15%. The bug was also in v2.
**Decision.** `scope(tighten)` covers all cases, and tightening is applied last in `apply()`. Regression test `test_stricter_law_overrides_a_loosening_approval`. The recovery check now treats the stricter rule as applying at any discount.
**Status.** Accepted.

## ADR-021 · Rule fidelity alongside "exact"
**Context.** "exact" (coverage >= .6, purity >= .8) marked approximated rules as found (e.g. a single 22% cap for a 21-29% term-scaled rule).
**Decision.** Also report fidelity: the share of each hidden rule's cases that the holdings decide like the rule, on a fresh sample. Recovery and fidelity are recomputed in `aggregate_v3.py` from the stored SQL.
**Consequences.** Approximations become visible (H5 0.85, H4 0.92). It still doesn't penalise over-approval; overall accuracy does.
**Status.** Accepted.

## ADR-022 · Point-in-time = each decision at its own month's version
**Context.** Reading the whole history at one version (end of month 35) silently includes every later edit; the first run measured 0.0% changed facts.
**Decision.** `as_decided(months)` is the UNION ALL of the month-t slice read `VERSION AS OF` the end of month t. Decisions are loaded one month per commit group, with a `month_versions` table.
**Consequences.** 11.6% of facts differ from today's table. Mining today's table misses the churn rule. Building the law on today's table costs 0.28 pts on real facts. Many Delta versions and one query per slice: fine at this scale, partition-pruned in production.
**Status.** Accepted.

## ADR-023 · Moot court on a Lakebase branch per candidate; compute disabled after the verdict
**Context.** Each candidate needs an isolated, auditable trial. Projects cap active endpoints, and read-write endpoints can't be deleted.
**Decision.** Create branch `t<run>-<id>` (TTL 7 days), write the candidate and verdict into the branch's registry, promote the verdict to production, then `update-endpoint spec.disabled=true`. The replay compute runs in DBSQL.
**Consequences.** About 5 s per branch. The audit trail is a real database state per trial. Honest scope: the branch isolates registry state; it does not run the replay.
**Status.** Accepted.

## ADR-024 · LLM proposes, replay disposes
**Decision.** Every LLM output that would change the law (new rule, merge) is compiled into a UC function and must pass the same moot court as mined rules. Rationales are written to the registry but never change decisions.
**Consequences.** All 3 plausible LLM proposals were rejected by replay; the law was protected.
**Status.** Accepted.

## ADR-025 · The decision agent explains; a checker enforces the executable law
**Decision.** The agent returns {decision, cites, because}. The checker re-executes the cited UC functions as the calling user (SQL API, OBO by construction) and compares the decision with the executable law; otherwise it falls back to the law.
**Consequences.** 0 wrong decisions shipped even with a weak model that followed an injection. Agent "accuracy" measures compliance, by design.
**Status.** Accepted.
